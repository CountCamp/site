Basishandelingen in R

naslag — base R en dplyr naast elkaar

Waarvoor deze pagina is: de handelingen die je in elke analyse nodig hebt, in twee talen naast elkaar. Geen les — naslag. Sla hem open terwijl je werkt.

Alles hieronder draait op de diamantjes: de twaalf steentjes uit het boek. Twaalf rijen die je in één oogopslag overziet, met genoeg kolommen om alles op te oefenen.

⬇ Download de data — diamantjes.csv

kolom wat
naam Anna, Bram, Cees … Leen
karaat gewicht van het steentje
glans 0–100
gladheid 0–10, hoe goed geslepen
merk golfje of sterretje
D 1 als het een sterretje is, anders 0
DxG D × gladheid — het product, voor moderatie

Twee talen, één taak. Links base R — dat is R zoals hij uit de doos komt. Rechts dplyr — een pakket dat dezelfde dingen doet met werkwoorden en een pipe. De pipe leest als “en dan”: data |> filter(...) |> arrange(...) is neem de data, en dan filteren, en dan sorteren. R heeft sinds versie 4.1 zijn eigen pipe |>; %>% uit dplyr doet vrijwel hetzelfde en zie je in ouder werk.

OpmerkingEenmalig — het pakket installeren 
install.packages("tidyverse")   # duurt een paar minuten, één keer
library(dplyr)                  # elke sessie opnieuw

1. Inlezen en wegschrijven

OpmerkingIn R
  • Base R
  • dplyr
d <- read.csv("diamantjes.csv")

# row.names = FALSE, anders schrijft R een kolom met rijnummers mee
write.csv(d, "mijn_versie.csv", row.names = FALSE)
library(readr)
d <- read_csv("diamantjes.csv")
write_csv(d, "mijn_versie.csv")

De valkuil van dag één: R zoekt het bestand in zijn werkmap. Weet je niet waar die is, dan getwd(). Staat het bestand ergens anders, dan geef je het hele pad — of makkelijker: zet je script en je data in dezelfde map en open het script via het bestand zelf, dan klopt de werkmap vanzelf.

3. Kolommen — kiezen, hernoemen, maken

OpmerkingIn R
  • Base R
  • dplyr
d$glans                                   # één kolom eruit
d[, c("naam", "glans")]                   # twee kolommen
names(d)[names(d) == "glans"] <- "schittering"   # hernoemen
d$per_karaat <- d$glans / d$karaat        # nieuwe kolom
d |> pull(glans)
d |> select(naam, glans)
d |> rename(schittering = glans)
d |> mutate(per_karaat = glans / karaat)

Let op het verschil. Base R verándert d als je d$per_karaat <- ... schrijft. Een dplyr-regel geeft alleen een nieuw resultaat terug; wil je dat bewaren, dan d <- d |> mutate(...).

OpmerkingIn R

5. Samenvatten, en per groep

OpmerkingIn R
  • Base R
  • dplyr
mean(d$glans)                                  # → 50
aggregate(glans ~ merk, data = d, FUN = mean)  # → golfje 40, sterretje 60
tapply(d$glans, d$merk, mean)                  # zelfde, andere vorm
table(d$merk)                                  # → golfje 6, sterretje 6
d |> summarise(gem = mean(glans))

d |> group_by(merk) |>
  summarise(gem = mean(glans), n = n())

d |> count(merk)

Dit is waar de pipe zijn geld verdient. “Neem de diamantjes, en dan per merk, en dan het gemiddelde” staat er in die volgorde — precies zoals je het zegt.

6. Twee tabellen aan elkaar — merge en join

Stel dat je er een tweede tabelletje bij hebt: waar elk merk geslepen wordt.

OpmerkingIn R
  • Base R
  • dplyr
slijperijen <- data.frame(
  merk      = c("golfje", "sterretje"),
  slijperij = c("De Vijl", "Sterrenstof"),
  plaats    = c("Antwerpen", "Amsterdam")
)

# by = de kolom die in beide tabellen staat
samen <- merge(d, slijperijen, by = "merk")
nrow(samen)    # → 12
slijperijen <- tibble(
  merk      = c("golfje", "sterretje"),
  slijperij = c("De Vijl", "Sterrenstof"),
  plaats    = c("Antwerpen", "Amsterdam")
)

samen <- d |> left_join(slijperijen, by = "merk")
nrow(samen)    # → 12

De sleutel is de kolom die in beide tabellen staat — hier merk. Wat je moet weten: merge houdt standaard alleen rijen die in allebei voorkomen, left_join houdt álle rijen van links en zet NA waar rechts niets had. Bij twaalf rijen zie je dat verschil niet; bij echte data wél, en dan is het het verschil tussen kloppen en stilletjes rijen kwijtraken. Tel dus altijd je rijen vóór en na een koppeling.

7. Wide en long — dezelfde data, andere vorm

Nu staat elk steentje op één rij met drie eigenschappen naast elkaar: dat is wide. Sommige functies (en bijna alle plot-pakketten) willen het andersom: één rij per meting, met een kolom die zegt wélke meting het is. Dat is long.

OpmerkingIn R
  • Base R
  • dplyr
# reshape wil precies weten wat er kantelt en hoe de nieuwe kolommen heten
lang <- reshape(
  d[, c("naam", "karaat", "glans", "gladheid")],
  direction = "long",
  varying   = c("karaat", "glans", "gladheid"),
  v.names   = "waarde",
  timevar   = "eigenschap",
  times     = c("karaat", "glans", "gladheid"),
  idvar     = "naam"
)
nrow(lang)    # → 36  (12 steentjes × 3 eigenschappen)

breed <- reshape(lang, direction = "wide",
                 idvar = "naam", timevar = "eigenschap")
library(tidyr)

# drie kolommen worden twee: een naam-kolom en een waarde-kolom
lang <- d |>
  select(naam, karaat, glans, gladheid) |>
  pivot_longer(cols      = c(karaat, glans, gladheid),
               names_to  = "eigenschap",
               values_to = "waarde")
nrow(lang)    # → 36

breed <- lang |>
  pivot_wider(names_from = eigenschap, values_from = waarde)

Waar iedereen op vastloopt: je moet drie dingen benoemen — wélke kolommen gaan kantelen, hoe de kolom gaat heten die hun namen opvangt, en hoe die met hun waarden. Teken het één keer op papier: twaalf rijen worden zesendertig, drie kolommen worden er twee. Dan klopt het beeld voorgoed.

8. Plotten

OpmerkingIn R
  • Base R
  • ggplot2
plot(d$karaat, d$glans)                    # puntenwolk
abline(lm(glans ~ karaat, data = d))       # de lijn erdoor

hist(d$glans)
boxplot(glans ~ merk, data = d)
library(ggplot2)

ggplot(d, aes(karaat, glans)) +
  geom_point() +
  geom_smooth(method = "lm", se = FALSE)

ggplot(d, aes(glans)) + geom_histogram(bins = 6)
ggplot(d, aes(merk, glans)) + geom_boxplot()

Het verschil in één zin: base tekent, ggplot bouwt op. In ggplot zeg je eerst wélke data en wélke kolom op welke as (aes), en daarna stapel je lagen met +. Dat voelt omslachtig bij één plaatje en wint zodra je er iets bij wilt.

De hele boog op één dataset

Waarom juist deze twaalf steentjes: er zit precies genoeg in om alles van het boek op te draaien.

OpmerkingIn R · van gemiddelde tot moderatie 
mean(d$glans)                             # H1  het gemiddelde
sd(d$glans)                               # H1  de spreiding
cor(d$karaat, d$glans)                    # H4  samenhang → .578
lm(glans ~ karaat, data = d)              # H4  de lijn → 17.9 + 32.1 · karaat
lm(glans ~ karaat + gladheid, data = d)   # H8  en dan valt karaat weg
lm(glans ~ D, data = d)                   # H9  groepen als getallen
lm(glans ~ gladheid * D, data = d)        # H10 verschil in verschil

Die vijfde regel is het hele hoofdstuk over confounding in één opdracht: los gezien voorspelt karaat de glans (b = 32.1), maar zodra gladheid meedoet, zakt karaat naar bijna nul (b = 0.98) en verklaart het model ineens 82% in plaats van 33%. Niet het gewicht maakte ze mooi — de slijper deed dat.
